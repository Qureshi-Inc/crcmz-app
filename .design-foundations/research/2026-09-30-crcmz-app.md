# CRCMZ App — Design Brief

**Summary:** A squad gaming dashboard for a small friend group (~10 people), built on a neon arcade aesthetic that must survive a structural upgrade to proper mobile/desktop layout without losing its soul.

**Date:** 2026-09-30  
**Status:** confirmed (amended 2026-09-30: device priority — mobile first)

---

## What this is

A private web app at `app.crcmz.me` that lets a gaming squad see each other's PSN presence, fire one-tap messages to the group, watch clips, track music shares, run giveaways, watch videos together, and interrogate a squad-aware AI. It also handles the PSN account-linking portal.

Primary use: quick glance at who's online, then either fire a soundboard button or navigate to a specific tool. Sessions are short and action-oriented, not sit-and-read.

## Who uses it

~10 gaming friends. They know each other. The tone is casual and in-jokey ("YES. WE HAVE ONE."). No onboarding needed — this is a known-audience product. Phones during gaming sessions and desktop while streaming or watching.

## Device priority (amended 2026-09-30, owner-confirmed)

**Mobile first. Desktop is barely used.** The phone is the product. Design every screen for a 375px thumb first, then adapt it up.

Desktop must not be embarrassing, but it is not a second product:
- **Default desktop treatment:** the persistent sidebar, plus content that uses the width sensibly. That covers the mobile layout reflowed into wider grids and columns, not a stretched phone column. There is no bespoke desktop design.
- **Desktop earns its own design only on jobs that are painful on a phone:**
  1. **Reel review / editor.** Main already ships a "desktop editor" (`2c7c2a6`). Inventory its current behaviour before specifying it.
  2. **Giveaway admin:** create, entries, and the lifecycle transitions.
  3. **WhatsApp:** stats tables and charts, Excel export, and history import.
- **Explicitly out:** keyboard hotkeys for soundboard buttons, multi-pane "second screen" dashboards, and hover-dependent interactions. Nothing may rely on hover, because the primary input is touch.

When mobile and desktop needs conflict, mobile wins.

## Brand & mood

**Neon arcade / late-night gaming session.** Not "professional dashboard" — the opposite. This feels like the UI inside a game, not an admin panel.

The aurora background (animated neon blobs — magenta, cyan, violet — blurred behind everything) is the single most recognisable visual element. The scanline/grid texture overlay reinforces the arcade feel. Together these make the app feel *alive* even when no data is changing.

Tone: irreverent, confident, a bit chaotic ("YES. WE HAVE ONE." as the tagline). The app is proud to be weird.

## Taste signals (dealer pins — do not change these)

- **Background**: near-black `#05030f` with animated neon aurora (3 radial blobs: hot magenta `rgba(255,47,214,.34)`, electric cyan `rgba(34,230,255,.30)`, violet `rgba(157,92,255,.28)`), blurred and slowly drifting. **Tune down blob opacity slightly** (target ~25–28% instead of 30–34%) so card text reads cleaner, but keep all three blobs, the drift animation, and the scanline grid texture overlay. These are mandatory.
- **Primary palette**:
  - Hot magenta / neon: `#ff2fd6`
  - Electric cyan: `#22e6ff`
  - Acid lime: `#8cff2b`
  - Violet: `#9d5cff`
  - Gold: `#ffd24a`
- **Typography**: Orbitron (Google Font, weight 600/800/900) for the wordmark, section headers, and numeric stat tiles. Rajdhani (Google Font, weight 500/600/700) for body text and button labels. Both fonts are load already in the legacy build and define the voice.
- **Cards**: Dark glass — `rgba(18,10,38,.66)` background, `rgba(255,60,200,.22)` border (neon-tinted). Subtle glass-morphism backdrop blur.
- **Soundboard buttons**: Each button has its own neon color (cyan, magenta/pink, lime, violet — per color class). The multi-color button grid is part of the brand, not incidental noise.
- **Gradient text on the wordmark**: cyan-to-magenta (`linear-gradient(90deg,#22e6ff,#ff2fd6)`), with a neon text-shadow. This must survive.
- **Chat Board**: The collapsible soundboard panel at the bottom is a core UX primitive. On Squad it sits to the right on desktop; on mobile it's a bottom sheet. The pager dots (shared board / personal board) are part of the interaction model.
- **CRCMZ logo**: The existing skull/gamer mascot PNG (`crcmz-logo.png`). Preserve.

## What's structurally broken (fix these — don't preserve)

The DESIGN.md from the previous redesign attempt articulates these well:

1. **Dropdown nav at the top** — no persistent orientation; you can't tell where you are or what else exists
2. **760px max-width on every screen** — half the viewport is empty on desktop for a table of 7 people
3. **Chat Board always visible** — sits on top of Ask AI's composer on every page (legacy code had a forced-collapse workaround)
4. **Neon used as surface color** — everything glows, nothing is emphasized; hierarchy came from randomness
5. **No type scale** — hierarchy was weight + color, not size

## Backend contracts that must not break

Every existing route and its request/response shape is a hard constraint. The new UI is a presentation layer over the existing FastAPI app in `server.py`. Nothing in this design changes the server.

Key contracts:
- `GET /api/squad` → presence list with `online_id`, `game`, `platform`, `trophy_level`, `platinums`, `golds`
- `POST /v2/send` → send message as logged-in user
- `POST /v2/squad` → send squad-up to squad group
- `GET|POST /api/soundboard` + `/api/soundboard/delete` → shared board
- `GET|POST /api/soundboard/personal` + `/delete` + `/order` → personal board
- `GET /clips` → clip catalogue with metadata
- `GET /api/clips/media?uid=` → streams the MP4; **bearer-only today** — session-cookie access is an in-scope backend change; returns 410 once the 14-day retention purges media
- Full verified route list: `grep -E '^@app\.' server.py` (133 routes, 2026-09-30)
- Auth: Zitadel OIDC session cookie; passkeys at `/auth/passkey/*`; machine token for Stream Deck plugin
- MCP server at `/mcp` (bearer auth, not cookie)

## Decisions confirmed by owner

| Question | Decision |
|---|---|
| Clip playback | **Build the endpoint and player.** Design assumes `GET /api/clips/{uid}/media` will exist; Clips screen shows thumbnails and inline playback. |
| Watch / Huddle | **Full integration.** Hardware available for real-device verification. Watch and Huddle are first-class screens, not hand-offs. |
| Desktop nav | **Persistent left sidebar.** Confirmed. |
| Aurora intensity | **Tune for readability.** Slightly less blob opacity, same vibe. |
| Chat Board scope | **Squad page only.** Right panel (desktop) / bottom sheet (mobile). Hidden on all other pages. |

## Navigation model (locked)

**Desktop:** persistent left sidebar. Sections: Squad, Clips, Slap, WhatsApp, Giveaway, Watch, Huddle, AI Coach, Ask AI, plus Settings and Admin at the bottom. Same sections as today, just discoverable.

**Mobile:** bottom tab bar — Squad · Watch · Clips · (overflow). Overflow sheet reveals: Slap, WhatsApp, Giveaway, Huddle, AI Coach, Ask AI, Settings, Admin. Every destination reachable in 2 taps.

**Chat Board placement:** Squad page only, as a right-panel column on desktop and a bottom sheet on mobile. Not visible on other pages — no workaround needed.

## Layout targets

- Mobile: 375px+ primary, thumb-reach tap targets (44px)
- Desktop: 1280px+ with sidebar, content filling the available width (not 760px everywhere)
- Wide breakpoint (1440px+): media grids (Clips) can expand further
- Reading-width exception: AI chat, Settings forms, and Portal stay at ~760px — long lines of text and forms shouldn't go full-width

## Context

**Problem:** Design a fresh CRCMZ interface at `/app` (served by a wiped-and-rebuilt `frontend/src`) that carries the original dashboard's neon-arcade identity and every workflow into a production-grade layout — touch-first on phones, denser with persistent navigation on desktop. The job is the squad's daily loop: see who's online, rally or ping the group, relive clips, and dip into side tools (Watch, Huddle, Music, WhatsApp, Giveaway, Coach, Ask AI, Settings, Admin).

**Constraints:**
- Source of truth: the original dashboard (`_DASHBOARD_TMPL` + routes in `server.py`) and the research doc. The old `frontend/src` and `docs/ux/` are not references.
- `/` stays untouched and default; `/app` is opt-in.
- Existing routes keep their contracts. Specs name endpoint, cadence and response shape per surface.
- Backend changes the design assumes (built in the follow-on code plan): session-cookie `/api/clips/media`; idempotent giveaway auto-reveal job; Stream Deck token auth (no UI).
- Slapshare panels whose shapes can't be verified against the live service are out of scope.
- Deliverable is design artifacts only; code gets its own plan after mock sign-off.

**Success criteria:** every original capability maps to a page spec or an explicit exclusion; every surface specifies loading / empty / error / stale / 429 / signed-out / forbidden states; all text + interactive pairs pass WCAG AA with neon as accent not surface; the mock reads as unmistakably CRCMZ at 375px and 1440px; design-review-agent returns no Critical findings.

## Chosen Approach

Rebuild the journey from the live dashboard template, not from screenshots or the prior attempt. Lock the DNA from the research taste signals, then fan out to system, words and data in parallel.

DAG: 1 → 2 → 3 → {4, 5, 6}. Gates: JOURNEY.md page specs before Phase 3; DESIGN.md locked before Phases 4–6.

### Phase 2: Flows + page specs
**Stage:** Discover
**Model:** opus (fable unavailable: data-retention 400)
**Doctrine:** journey, usability, interaction, ai-native
**Gate:** Full

**Goal:** Flows for the key workflows and one page spec per destination, with the backend contract and full state matrix.

**Scope:**
- IN: flows for soundboard fire/quick-send, Squad Up, clip review + playback, Watch join, Huddle join, giveaway lifecycle, Ask AI, portal link; page specs with mobile + desktop layouts
- OUT: visual styling

**Constraints:** each page spec names endpoint, poll cadence and response fields; states = loading, empty, error, stale, 429 (Retry-After), signed-out, forbidden, 410-purged (clips), in-call; the Watch/Huddle mini-bar persists across routes.

**Mock-review carry-overs (wireframe review 2026-09-30):**
- Major: the mobile Squad peek (collapsed Chat Board + tab bar) must not exceed ~12% of a 375×800 viewport. Use a slim handle with a Chat trigger, and show the composer only when the sheet is open. Hype and stat tiles go compact on mobile.
- Minor:

  - the composer placeholder fits at 375px
  - the open sheet has a scrim
  - the hype meter shows its scale or reference
  - the sidebar and bottom bar have distinct accessible nav labels
  - desktop nav rows are ≥44px

## Follow-ups for the code plan

- Session-cookie access to `/api/clips/media`
- Idempotent giveaway auto-reveal job
- Stream Deck `CRCMZ_MACHINE_TOKEN` migration
- Server-side admin gate on `/api/clips/{uid}/resend`
- Tree test the IA with ~5 squad members before coding (job stories are hypotheses)
- Found in Phase 2 (JOURNEY.md B-4…B-9):
  - B-4: the `psn_send` rate limit is keyed on client IP, which is probably one shared bucket behind the tunnel
  - B-5: `/api/giveaway` leaks the winner in `draws[]` to members before reveal. **Security/fairness: strip it server-side.**
  - B-6: `/v2/send` silently falls back to crcmz-mod without saying which account sent
  - B-7: `/api/hype` masks errors as "cold, 0 msgs"
  - B-8: `/status`, `/api/video-jobs` and `/api/pipeline-status` service health have no role check
  - B-9: the passkeys endpoint returns `[]` when its upstream fails
- Phase 3 → Phase 4: the mascot needs a 72px top bar, but PS-0/PS-1 say 48px. A fixed 72px bar plus the tab bar and Chat handle is ~21% of a 375×800 screen. Phase 4 must either condense the bar to ~48px on scroll or let it scroll away on mobile, then sync JOURNEY.md.
- Phase 3 review Minor → Phase 4: `--wordmark-glow` doesn't render, because text-shadow is suppressed under `background-clip:text` + transparent colour. The pinned neon text-shadow must be delivered with `filter: drop-shadow()` on a wrapper.
- Phase 4 review note → Phase 6: `--text-4xl` has no rendered specimen yet. Exercise it in the data-surface stat numerals.
- Phase 2 review Minors (fold in during Phase 5):
  - PS-6 `in-call` row should cross-reference F-5's Huddle auto-mute
  - PS-12 status card is missing the "Expiring in N days" state that PS-10 has
  - PS-2 resend contract should restate F-0's 190 s timeout
- Shell-level Watch/Huddle session owner; URL-encode `message_uid` (`#`); `/clips` needs `Accept: application/json`

## Verification plan

- Every DW item above, checked by the design-review-agent against the artifact.
- Dirty cases:
  - DESIGN.md not locked → mock runs in wireframe mode and is flagged (Phase 3 gate)

  - magenta button fill below 4.5:1 → token rejected (DW-3.2)
  - a gesture-only capability without a visible equivalent → Phase 1 fails DW-1.1
